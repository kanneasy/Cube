# References

Source material that grounds the build — both the user's existing materials and Builder's own research. These are not specs (no MSFM annotations). The spec, build, design, voice, and product work all read what's here to understand the domain and match what already works.

What goes here:
- **The user's materials** — instructions or prompts from a ChatGPT/other assistant, PDFs, notes, prior research, brand assets, a site or screenshot to match.
- **Builder's research** — findings the `researcher` agent gathers (e.g., how to get great results from a specific tool, domain conventions, prior art), with sources cited.

How it's used: read everything here before authoring. When a reference defines a **methodology** — how to structure a prompt, how a study should read, which settings produce good output — treat it as the authority for that behavior and ground the spec and code in it. Don't reinvent or contradict it without a reason.
