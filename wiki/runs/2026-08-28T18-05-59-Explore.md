**Entry/priority rules** (`onDown`, L312):
1. `event.preventDefault()`, record pointer in `this.pointers` map (L314).

## 5. Whole-body 3D rotation (orbit)

**One finger on background** → `orbit` state → `renderer.orbitBy(dx, dy)` per move event (gestures.ts:407):

```ts
// renderer.ts:315
orbitBy(dxPx: number, dyPx: number): void {
  const travel = Math.hypot(dxPx, dyPx);
  if (travel === 0) return;
  const axis = new THREE.Vector3(dyPx, dxPx, 0).normalize();
  const angle = travel * (Math.PI / this.faceWidthPx());
  this.orientation.premultiply(new THREE.Quaternion().setFromAxisAngle(axis, angle)).normalize();
}
```

Incremental screen-space quaternion, left-composed, renormalized. **No clamp, no pole, no gimbal lock, no snap-to-pose.** Gain is 180° per face-width of drag (≈0.95°/px at rest), so a zoomed-in cube is heavier to spin.

**Momentum** (`glideOrbit`, L555): velocity from the 60ms history window (`first`→`last`, never a single frame), axis captured once and screen-fixed, `speed *= exp(-dt/400ms)`, stops below 26 px/s. Skipped entirely under reduced motion (L556).

**Multi-touch: yes, already implemented.** `PinchDrag` (L114) — second finger promotes from *any* state:
```ts
// gestures.ts:387-401 (onMove, pinch branch)
this.renderer.orbitBy(centre.x - drag.lastCentroid.x, centre.y - drag.lastCentroid.y);
drag.lastCentroid = centre;
if (!drag.engaged &amp;&amp; Math.abs(span - drag.startSpan) &lt; PINCH_THRESHOLD_PX) return;
drag.engaged = true;
this.setZoomRubberBanded(drag.startZoom * (span / drag.startSpan));
```
Centroid translation orbits **before** the 12px span threshold engages, so two fingers always orbit even at `ZOOM_MAX` where no background is grabbable.

**Pinch-to-zoom: yes.** 1:1 span ratio, no momentum, log-space rubber-band past limits (`setZoomRubberBanded`, L291) with a 17% asymptotic ceiling, springing back on release via `settleZoom` (L303).

**Two-finger *rotate* (twist/roll): NO.** No `atan2` of the pointer pair anywhere. The design deliberately rejected it — `wiki/runs/2026-08-26T20-36-03-builder:design-expert.md:48`: "Twist-to-roll on the pinch — nothing to gain on an object with 24 identical orientations." Note the trackball also produces **no roll** about the view axis at all, since `orbitBy` always builds an axis in the z=0 plane.

**Double-tap → view reset** (`resetView`, L595): quaternion SLERP to `defaultOrientation()` + lerp `f` to `ZOOM_REST`, 260ms, `1-(1-t)³`.

## 7. Where the "hard swipe" requirement comes from

The gain itself is *not* the culprit — 28px to commit is light. Four real mechanisms, in order of likely impact:

**(a) `if (this.animating) return;` — gestures.ts:346.** Every pointerdown is swallowed while the turn spring runs. The spring only exits when `|x-to| ≤ 0.0015 rad AND |v| ≤ 0.02` (L666), which at the 16ms frame cap is ~170–200ms. No `pending` drag is created, so continuing to drag does nothing — the touch is simply gone. Turning at speed loses every second turn. `animation` is shared with `resetView` (260ms) and the reduced-motion glide, so those block input too.

**(b) The axis lock uses the noisiest 8px of the stroke, then discards everything perpendicular.** `along = dx·t.x + −dy·t.y` projects onto the tangent locked at L422. A drag 45° off the locked tangent loses 29% of its travel; 60° off loses 50%. A curving thumb whose first 8px disagrees with its intent gets a layer that barely moves, and the natural response is to push harder rather than differently.

**(c) Turn velocity is a single-frame delta, unlike orbit.** L457: `drag.velocity = (angle - drag.lastAngle) / dt`. The `VELOCITY_WINDOW_MS = 60` guard exists only in `glideOrbit` — and its own doc comment (L44–49) states the reason: *"On iOS the last pointermove before a lift routinely carries a 2ms dt and a jitter pixel."* The turn path is unprotected, so it fails both ways: a jitter pixel fires a phantom flick, and any pause before lifting zeroes the velocity and kills the flick branch, forcing the full 45°. Also, once `angle` saturates at `LIVE_CLAMP`, it stops changing, so velocity decays to 0 for the rest of a fast swipe.

**(d) There is no grab acknowledgement at all.** `src/interfaces/@brand/visual.md:150-157` requires, within 60ms, a sticker lift to `k × 1.06` plus a 1px `rgba(255,255,255,0.22)` hairline tracing the layer boundary — and lines 396–400 call the hairline *"load-bearing… the only proof the touch registered"* because there are no haptics. **Neither is implemented.** `renderer.ts` has no lift or outline code; `App.tsx:107-111`'s `onGrab` only unlocks audio and dismisses the first-run flag. Nothing confirms the touch until the layer visibly moves.

Historical note: `git show 8b8413e` ("Turn the cube wherever you touch it, and only ever by a quarter") is where `LIVE_CLAMP` went 180° → 90°, because *"A strong swipe committed two quarters at once."* That fix is intact and correct — it is not the cause of the current stiffness.
