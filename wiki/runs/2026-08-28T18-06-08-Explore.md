## 2. `dist/scripts/normalize-icon.mjs` — what it actually does

Path: `/Users/erickanney/builder/projects/quarter-turn/.claude/worktrees/cube-rotation-face-controls-56433f/dist/scripts/normalize-icon.mjs` (3,663 B). It is a thin Node wrapper that shells out to `python3 -c` with an inline Pillow script, once per output size.

Header comment (verbatim, the design rationale):
&gt; Two defects in the generated render are compositing-level rather than creative, and two attempts with identical `transparent: false` requests differed on the first of them -- so they are provider non-determinism, not something the brief can control. Fixing them deterministically here costs no generation attempts and cannot regress:
&gt;   1. The provider returns real alpha even when opaque was requested. The brief says "pure black background", and an icon with a transparent field behind it does something unpredictable once OS compositing touches it.
&gt;   2. It does not centre reliably. The maskable variant crops to a circle, so an off-centre master clips the cube unevenly -- and the checker cannot see the problem at all while the surround is transparent, because its border-band detector needs opaque pixels to measure.

Constants:
```js
const CONTENT_FRACTION = 0.8;   // "The safe zone the brief specifies, and what the maskable crop depends on."
const MASTER = 1024;
const outDir = join(dirname(source), 'icons');
```

Per-output algorithm (the Pillow block), in order:

1. **Open + `convert("RGBA")`.**
2. **Find the content bounding box.** Take `alpha.getbbox()` if the alpha channel has any non-255 value; otherwise fall back to a luminance threshold: `im.convert("L").point(lambda v: 255 if v &gt; 24 else 0)` then `.getbbox()`. Final fallback is the whole image. The comment is load-bearing:
   &gt; Falling back to a luminance threshold would be wrong here: the cube's own grid gaps are near-black graphite and would be read as background.
   (i.e. threshold is only used on an already-opaque master, where it measures against the black field.)
3. **Crop to that box.**
4. **Resize to the safe zone.** `target = round(size * 0.8)`; `scale = min(target/w, target/h)`; resize with `Image.LANCZOS`, preserving aspect. So content occupies **80 % of each output on its longer axis**.
5. **Alpha flatten + centre.** New canvas `RGBA (size, size)` filled `(0, 0, 0, 255)` — **opaque true black, always**. Content pasted at `((size - w)//2, (size - h)//2)` using itself as the alpha mask.
   &gt; Opaque black, always. This is the half the provider keeps getting wrong.
6. **`canvas.convert("RGB").save(out, "PNG", optimize=True)`** — the alpha channel is dropped entirely from every output.
7. Prints measured L/R and T/B margins per file.

## 6. `~/builder/bin/image-check.mjs` — what it checks

Path: `/Users/erickanney/builder/bin/image-check.mjs` (22,091 B). Zero dependencies — a self-contained PNG decoder using `node:zlib`.

```
node bin/image-check.mjs &lt;project&gt; [--dir dist/web/public] [--json] [--bump] [--type icon|og|photo|cutout|seed-data]
```
Scans every `*.png` in `&lt;project&gt;/&lt;--dir&gt;` (default `dist/web/public`), writes `&lt;project&gt;/.image-check.json`, **exits 1 when any asset fails**. `--type` declares intent for sidecar-less files and applies to *all* of them (it warns about this). `--bump` increments an iteration counter.

Checks, with their exact fail conditions:

1. **No sidecar** → `warn`: "no .gen.json sidecar — size, transparency, and hygiene checks skipped." (These checks then genuinely do not run.)
2. **Decode failure** → `fail` with the decoder's message. Rejects interlaced PNGs and bit depths other than 8/16.
3. **Blank/solid render** → `fail` if `distinctQuantizedColors &lt;= 4 || lumStd &lt; 2` → "near-uniform image … likely a blank or solid render".
4. **Size ignored** → `fail` if `sidecar.requested.size !== "&lt;w&gt;x&lt;h&gt;"`.
5. **Transparency triad** (only when `sidecar.transparencyRequested`):
   - no alpha channel → `fail`
   - alpha channel present but zero pixels with `a &lt; 250` → `fail` "the background was not removed"
   - all four corners `a &gt; 32` → `fail` "the subject was not isolated"
6. **Letterbox / mockup framing** — `borders()` measures the depth of a *uniform* flat band at each edge (tol 6, fully-transparent lines excluded). `fail` if all four sides ≥ 8 % of the dimension; `warn` if ≥ 2 sides are ≥ 6 %. **This is the check the commit message says was blinded by the transparent master** — the border-band detector needs opaque pixels to measure.
7. **Icon legibility at 48 px** — runs when `sidecar.type === 'icon'`, or `--type icon`, or (sidecar-less, no `--type`) the filename matches `/icon/i`. Downsamples to 48×48 luminance, then uses **p99 gradient magnitude (`edgeStrength`) and tonal `range`**, not mean gradient:
   - `fail` if `edgeStrength &lt; 0.05 || toneRange &lt; 0.2` → "dissolves at icon size … no legible silhouette"
   - `warn` if `edgeStrength &lt; 0.12` → "soft at icon size"
   - Calibration note in the source: "real renders (p99 0.29-0.52, range 0.53-0.99) versus gradient mush (p99 0.003, range 0.14)."
8. **Pixel-identical duplicates** → `fail` "pixel-identical to &lt;other&gt; — the seed or prompt did not vary".
9. **Superseded-attempt hygiene** — groups by `type@dims` and flags extras as leftover regeneration candidates. Skipped inside `.image-bakeoff/`. Explicitly keyed on dimensions too, because "A PWA icon ladder (1024/512/192/180 derived from one master with sips) is the most common multi-icon case there is, and it is correct — only same-size duplicates are leftover candidates."

Also **reported, not gated**: per-file dominant top-3 colors with `share`, and the nearest brand token by CIELAB ΔE. Brand colors come from **`&lt;project&gt;/src/interfaces/@brand/tokens.json`**, flattened by walking every string that matches `#rgb`/`#rrggbb`. Plus `alphaChannel`, `transparencyDelivered`, `transparentPx`, `colors`, `lumStd`, `borderPx`, `edgeStrength`, `toneRange`.

Explicitly *out of scope*: "Taste — is the subject right, is the text real, is it on brand — is the image-critic's job. This runs first and free."

## Summary of the full pipeline

```
src/interfaces/@brand/visual.md  ("The mark and the icon" brief)
   │  copy-pasted as argv[2]
   ▼
node ~/builder/bin/gen-image.mjs &lt;project&gt; "&lt;brief&gt;" --type icon --size 1024x1024
   │  codex exec → gpt-image-2, native 1254x1254 → sips downscale to 1024
   ▼
&lt;project&gt;/dist/web/public/icon-&lt;sha1[0:8]&gt;.png  +  .gen.json     ← default output dir
   │  (manually moved to dist/assets-source/ so the SW doesn't precache a 900KB master)
   ▼
node ~/builder/bin/image-check.mjs &lt;project&gt;      ← deterministic gate
builder:image-critic subagent                     ← taste gate, 32-point rubric
   │
   ▼
node dist/scripts/normalize-icon.mjs dist/assets-source/icon-ea2543bc.png
   │  python3 + Pillow: alpha bbox → LANCZOS to 80% → paste on opaque black → RGB
   │  writes to dirname(source)/icons/  →  dist/assets-source/icons/
   ▼  (manually copied)
dist/web/public/icons/{icon-1024,icon-512,icon-512-maskable,icon-192,apple-touch-icon-180}.png
   │
   ├─→ vite.config.ts VitePWA manifest.icons  (192 any, 512 any, 512 maskable)
   └─→ dist/web/index.html  &lt;link rel="apple-touch-icon" href="/icons/apple-touch-icon-180.png"&gt;

dist/web/public/favicon.svg  ← hand-authored, &lt;link rel="icon"&gt;, re-read every page load
dist/web/components/Mark.tsx ← same mark in React, currentColor, for in-app chrome
```

**Three loose threads worth knowing before touching any of this:**
1. `visual.md` still says `bin/flatten-icon.mjs`; the script is `dist/scripts/normalize-icon.mjs`.
2. `normalize-icon.mjs` writes to `dirname(source)/icons`, so neither documented invocation lands on the served path — the copy into `dist/web/public/icons/` is a manual, unrecorded step.
3. `icon-512.png` and `icon-512-maskable.png` are byte-identical; the maskable variant gets no extra padding beyond the shared 80 % `CONTENT_FRACTION`. Android's maskable safe zone is a circle of ~80 % diameter, so an 80 % *bounding-box* fit means the cube's corners sit right on the crop boundary.
